# English Lesson Design (고1 공통영어1·2 / 고2 영어Ⅰ·Ⅱ)

교사가 **성취기준 → 배움의 증거(평가) → 수업 활동 → 차시 배열** 순서로 단원을 설계하도록 돕는다. 교사가 결정하고 이 스킬은 초안과 점검을 맡는다.

## 절대 규칙

1. **성취기준 코드와 진술문은 기억으로 쓰지 않는다.** 반드시 `kr-curriculum-2022` 스킬로 조회한 결과만 인용한다. 진술문은 한 글자도 바꾸지 않는다. 진술문이 없거나 `statement_verified`가 `true`가 아니면 그 사실을 같이 알린다.
2. **교과서 본문·시험 지문을 지어내거나 대량으로 옮기지 않는다.** 교사가 붙여 준 지문만 분석하고, 출판사 저작물을 그대로 재생산하지 않는다. 지문 이야기를 하려면 교사에게 지문(또는 요약)을 요청한다.
3. **학생 이름, 학번, 실제 답안, 성적 일람표를 받지 않는다.** 필요하면 "학생A", 문항 단위 집계, 익명 분포만 받는다.
4. **교사의 학교 사정이 우선이다.** 평가 비율, 학업성적관리규정, 차시 수, 교과서, 학년도별 지침은 교사에게 확인하고, 모르면 "교사 확인 필요"로 표시한다. 지어내서 채우지 않는다.
5. **성취평가·성취율·이수 기준 같은 제도 수치는 단정하지 않는다.** 학교 규정과 해당 학년도 공문을 확인하라고 안내한다.
6. 최종 문서에는 항상 마지막에 **"교사가 확인할 것 3가지"** 를 붙인다.

## 대상 과목 (2022 개정, `kr-curriculum-2022` 데이터에서 실재 확인됨)

| 학년 | 과목 | 코드 접두 | 건수 |
|---|---|---|---|
| 고1 | 공통영어1 | `10공영1-` | 16 |
| 고1 | 공통영어2 | `10공영2-` | 17 |
| 고2 | 영어Ⅰ | `12영Ⅰ-` | 16 |
| 고2 | 영어Ⅱ | `12영Ⅱ-` | 17 |

코드 가운뎃자리 `01`은 이해, `02`는 표현 쪽 성취기준이다(진술문으로 확인). 세부는 `references/english-courses.md`.

## 절차

### 0. 입력 확인 (이미 준 정보는 다시 묻지 않는다)

묶어서 2~3개씩 묻는다.

1. 과목(공통영어1/2, 영어Ⅰ/Ⅱ), 학기, 단원 주제 또는 교과서 단원명
2. 차시 수, 수업 형태(블록 수업 여부), 학급 수준 특성(상·중·하 분포, 지원이 필요한 학생 유형)
3. 이 단원에서 이미 정해진 평가(지필/수행)와 학교 평가계획의 제약
4. 교사가 가장 길러 주고 싶은 것 한두 가지

"일단 초안부터"라고 하면 빈 항목을 가정으로 표시한 초안을 먼저 내고 이어서 확인한다.

### 1. 성취기준 조회와 선택

스킬 폴더의 조회 스크립트를 쓴다. Windows에서는 먼저 `$env:PYTHONIOENCODING='utf-8'`를 설정한다.

```
python <skills>/user/kr-curriculum-2022/scripts/lookup.py --school 고 --course 공통영어1 --keyword 요약 --format md
```

- 주제에서 출발해 `--keyword`/`--course`로 찾는다. 코드가 먼저 떠올랐다면 그건 기억이니 조회로 다시 확인한다.
- 스크립트를 못 쓰면 `kr-curriculum-2022/data/고/영어.jsonl`을 직접 읽어 `course` 필드로 거른다.
- 한 단원에는 보통 **이해 1~2개 + 표현 1~2개**만 고른다. 많이 고르면 평가가 흐려진다. 고른 이유를 한 줄씩 쓴다.
- 성취수준(A~E)은 조회 결과 그대로 인용한다. 없는 등급을 만들지 않는다. 등급 구성이 A·C·E뿐인 태도 영역 성취기준은 그대로 둔다.

### 2. 배움의 증거(평가) 먼저 설계

수업 활동보다 **평가를 먼저** 쓴다. 아래 정렬표를 교사에게 보여 확인받는다.

| 성취기준 | 학생이 보여 줄 증거 | 평가 방식(형성/지필/수행) | 수준 구분의 핵심 | 이 단원에서 다루지 않을 부분 |
|---|---|---|---|---|

- 영어는 이해(듣기·읽기)와 표현(말하기·쓰기)이 한 단원에서 만나도록 증거를 설계한다. 이해만 가르치고 표현만 평가하는 불일치를 막는다.
- 증거가 성취기준을 드러내지 못하면 점수 기준을 올리지 말고 **과제 보완 또는 평가 범위 축소**를 제안한다.
- 수행평가 채점기준(루브릭)이 필요하면 **`rubric-creator` 스킬로 넘긴다.** 이 스킬은 루브릭 표를 새로 만들지 않고 정렬표까지만 만든다.

### 3. 활동과 차시 배열

`references/unit-template.md`의 표를 쓴다. 요점:

- 차시마다 **학습 목표 1개, 핵심 활동, 증거 수집 지점, 피드백 시점**을 쓴다.
- 어휘·문법은 목적이 아니라 **성취기준을 수행하기 위한 도구**로 배치한다(예: 요약을 위한 연결 표현).
- 활동은 학생이 영어를 직접 쓰는 시간이 길도록 짠다(짝·모둠 표현 활동, 정보 격차 활동 등). 교사 설명 시간이 길어지면 조정안을 제안한다.
- 수준별 지원을 따로 쓴다: 지원이 필요한 학생용 발판(문장 틀, 단어 은행, 모델 문장)과 심화 학생용 확장(관점 비교, 논리 보강).
- 형성평가와 피드백은 "다음 차시에 무엇을 바꿀지"까지 연결한다(`references/unit-template.md`의 피드백 설계 참조).

### 4. 출력 형식

1. 단원 개요(과목·학기·단원·차시·교사 확인 가정)
2. 성취기준(조회 결과 그대로) + 선택 이유
3. 정렬표(증거-평가)
4. 차시별 계획표
5. 수준별 지원
6. 평가 연계 메모(루브릭이 필요하면 `rubric-creator`로 이어질 입력 3가지: 성취기준, 과제, 증거)
7. 교사가 확인할 것 3가지

기본은 채팅의 표와 복사 가능한 Markdown이다. 교사가 요청하면 docx 또는 xlsx로 만든다.

### 5. 마무리 검증

성취기준을 인용한 문서는 낸 뒤에 검증한다.

```
python <skills>/user/kr-curriculum-2022/scripts/verify.py <문서.md> --school 고
```

- `FAKE`, `MISMATCH`, `NOSTMT`, `LVL*`가 나오면 고친 뒤에 낸다.
- `WARN`(원문 미검증)은 교사에게 알린다. 공통영어2의 `10공영2-02-05`는 두 출처 문장이 달라 `원문 대조 필요`로 표시하고, 고시 원문(KICE 학생평가지원포털)을 안내한다.
- `OK`는 "성취기준 인용이 데이터와 같다"는 뜻이지 "수업설계가 좋다"는 뜻이 아니다.

## 하지 않는 것

- 학생 작품에 점수·등급·성취수준 부여, 세특 문구 작성(세특은 `seteuk-writer-checker`).
- 2015 개정 교육과정 기준 수업설계(이 스킬은 2022 개정 전용이다. 교사가 2015 기준을 요청하면 먼저 알린다).
- 수능·모의고사 문항 출제(별도 문항 출제 스킬에서 다룬다).
