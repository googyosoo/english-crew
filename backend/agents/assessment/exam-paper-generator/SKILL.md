# Exam Paper Generator (한국 고등학교 영어 내신 원안지 생성기)

심인고 영어과 원안지(2025-1중간/기말, 2025-2중간/기말, 영어II, 심화영어I) 패턴을
학습한 출제 스킬. **1지문당 1문항** 원칙(strict)으로 시험지(**.hwpx**, 원본 예시
파일과 동일 서식)와 정답·해설지(.docx)를 별도 생성한다.

## 핵심 사양 (변경 금지)

| 항목 | 값 |
|---|---|
| 발문 언어 | 한국어 |
| 선택지/지문 | 영어 (서술형 일부는 한국어 답안 가능) |
| **시험지 출력 형식** | **.hwpx** (첨부 예시 파일과 동일 형식 — docx 아님) |
| 정답·해설 출력 형식 | .docx |
| 지문-문항 매칭 | **strict 1:1** (지문 N개 → 문항 N개) |
| 난이도 | 각 문항 [상/중/하] 라벨 + 차등 배점 (3 / 3.5 / 4 / 4.5점) |
| 표준 구성 | 객관식 18 + 서술형 5 = 23문항 (사용자가 N, M 지정 가능) |
| 창의 유형 | 객관식 18문항 중 1-2개, 서술형 5문항 중 1개까지 허용 |
| 정답 표시(hwpx 안) | 노란 형광펜(원본 원안지 관행 그대로) |

## 이 스킬이 만드는 것 / 못 만드는 것

`scripts/build_exam.py` 는 실제 원안지 hwpx 파일 안의 검증된 문단·표 블록을
복제해서 텍스트만 갈아 끼우는 방식으로 동작한다(자세한 이유는
`references/hwpx_build_guide.md` 참조). 그래서:

- 두 개의 실제 원안지를 베이스 템플릿으로 지원한다 — `meta.template` 로 선택
  (`references/hwpx_build_guide.md` 참조):
  - `"영어II"` (기본값) — `영어II_원안지.hwpx` 골격
  - `"공통영어2"` — `2025_1학년_2학기_기말고사_원안최종.hwpx` 골격
- 지원되는 9가지 블록 유형(`plain_choice5`, `embedded_underline`, `marker_passage`,
  `insertion`, `ab_table`, `abc_table`, `order_choices`, `translation_blank`,
  `word_box`)은 **원본과 동일한 글꼴·표·선택지 자동번호·정답 형광펜**으로 100%
  재현된다. 단 `abc_table`(어법 A/B/C 박스)은 `"공통영어2"` 템플릿에만 표본이 있어
  그 템플릿을 골랐을 때만 쓸 수 있다.
- `references/question_types_objective.md` / `question_types_descriptive.md` 의
  "HWPX 조립 매핑" 표에서 "⚠️ 수동 마무리"로 표시된 소수 유형(표·요약 빈칸 채우기,
  어법 오류 표 등 다중 셀 표 구조)은 이번 버전에 없다. **Step 2 유형 매칭 단계에서
  이 표를 먼저 확인하고, 가능하면 지원 유형만으로 18+5 구성을 짠다.**

## 워크플로 (반드시 순서대로)

### Step 1. 입력 확인
사용자에게 다음을 확인한다 (이미 제공된 정보는 건너뛴다):
- **지문 파일**: pdf/docx/txt/md (여러 개) 또는 인라인 텍스트
- **문항 수**: 객관식 N개 + 서술형 M개 (기본값: 18+5)
- **지문 개수 ≥ N+M** 인지 확인. 부족하면 사용자에게 알리고 중단.
- **시험 정보**: 학교명/학년/학기/시험명/과목명 + 어느 템플릿(`meta.template`:
  "영어II" 또는 "공통영어2")을 쓸지 (build_exam.py의 `meta`에 그대로 들어감 — 안
  물어보고 넘어가면 고른 템플릿의 기본값이 그대로 찍혀 나가니 **반드시 확인**한다.
  `abc_table` 유형이 필요하면 반드시 "공통영어2"를 선택해야 한다)

지문이 PDF/DOCX인 경우 `pdf-reading` 또는 `docx` 스킬로 텍스트를 먼저 추출한다.

### Step 2. 지문 분석 및 유형 매칭
각 지문에 대해 다음을 판정한다:

1. **지문 특성 태깅**: 길이(어휘 수), 주제(설명문/논설문/내러티브/실험연구/안내문 등), 핵심 논리 구조(인과/대조/예시/순차)
2. **유형 적합도 매칭**: `references/question_types_objective.md` 와 `references/question_types_descriptive.md` 를 **반드시 읽고** 각 지문에 최적 유형을 배정한다. 이때 각 파일 하단의 "HWPX 조립 매핑" 표에서 지원되는 `build_exam.py` type을 함께 확인한다.
3. **유형 다양성 보장**: 표준 구성(18+5)일 때 객관식은 최소 10개 이상의 서로 다른 유형, 서술형은 가능한 여러 유형이 나오도록 분배(단, 지원 8종 블록 안에서).
4. **난이도 균형**: 상 30%, 중 40%, 하 30% 비율 목표 (`references/difficulty_calibration.md` 참조).
5. **창의 유형 1-2개**: 적절한 지문이 있을 때만 `references/creative_types.md` 의 유형 사용(대부분 `plain_choice5`로 구현). 억지로 끼워 넣지 말 것.

### Step 3. 문항 작성
각 문항을 다음 표준에 맞춰 작성한다:

- **발문**: 한국어. 첨부 예시 파일들의 발문을 **그대로 차용**한다 (예: "다음 글의 요지로 가장 적절한 것은?", "다음 글의 밑줄 친 부분 중, 어법상 틀린 것은?"). 새 표현을 만들지 않는다.
- **배점 표기**: 발문 끝에 `[3점]` `[3.5점]` `[4점]` `[4.5점]` 중 난이도에 따라 stem 텍스트에 직접 포함시킨다(자동화 안 됨).
- **문항/선택지 번호**: 객관식 번호, 선택지 ①②③④⑤, 서술형 【서술형 N】은 **전부 build_exam.py가 자동으로 붙인다.** stem이나 choices 텍스트에 번호를 직접 넣지 않는다 (`assets/exam_template.md` 참조).
- **선택지**: 5지선다. 정답 1개, 매력적 오답 4개. 오답은 지문에 단어가 등장하지만 결론이 빗나가거나, 부분만 맞거나, 과잉/축소된 진술.
- **서술형 조건**: `<조 건>` 박스, `<Word Box>` 박스는 `word_box` 빌더가 자동 처리.

각 유형별 정확한 작성 규칙은 `references/question_types_objective.md` 와 `references/question_types_descriptive.md` 를 참조. 각 블록 유형이 요구하는 정확한 JSON 파라미터는 `references/hwpx_build_guide.md` 를 참조.

### Step 4. 검증 (조립 전 self-check)
다음 체크리스트를 통과해야 한다. 실패 항목이 있으면 수정한다:

- [ ] 지문 수 = 문항 수 (strict 1:1)
- [ ] 모든 문항이 지원되는 9종 블록 유형 중 하나에 매핑되는가? (`abc_table` 을 썼다면 `meta.template`이 "공통영어2"인가?) 아니면 Step 2로 돌아가 유형 재배정, 또는 사용자에게 수동 마무리 필요함을 사전 안내
- [ ] 정답이 지문에서 명확히 도출되는가? (근거 문장 식별 가능)
- [ ] 오답 4개가 지문 정보로 명확히 배제 가능한가?
- [ ] 어법 문항: 틀린 곳이 정확히 1곳, 한국 고교 교과서 문법 범위 내인가?
- [ ] 빈칸 문항: 정답 외 선택지가 빈칸에 들어가면 논리적으로 부자연스러운가?
- [ ] 순서/삽입 문항: 정답 배열이 유일한가? (다른 배열도 말이 되면 안 됨)
- [ ] 난이도 분포가 균형(상 약 30%, 중 약 40%, 하 약 30%)인가?
- [ ] 발문이 원본 시험지 표현과 일치하는가?
- [ ] 모든 stem/choices 텍스트에 번호(1. / ① / 【서술형N】)를 **직접 넣지 않았는가**? (자동 번호와 중복되면 "1. 1. 다음 글의..." 처럼 이중 표시됨)
- [ ] 서술형 채점 기준이 명확한가? (정답이 1개로 수렴 또는 부분점수 기준 명시)

### Step 5. hwpx 조립 (시험지)
1. Step 3의 모든 문항을 `references/hwpx_build_guide.md` 형식의 JSON 스펙으로
   정리해 파일로 저장한다.
2. `python3 scripts/build_exam.py <spec.json> <출력경로>.hwpx` 실행.
3. 출력에 `[FATAL]` 이 하나라도 있으면 **그 파일을 사용자에게 전달하지 말 것.**
   스펙을 고쳐 재실행한다. `[OK] 검증 통과 ...` 를 반드시 확인한다.
4. 파일명 규칙: `{학년}_{학기}_{시험명}_{과목명}_문제지.hwpx`
5. 완성된 hwpx를 `/mnt/user-data/outputs/` 로 두고 `present_files` 로 전달.

### Step 6. 정답·해설 (docx, 별도 파일)
1. **반드시 `/mnt/skills/public/docx/SKILL.md` 를 먼저 읽는다.**
2. `assets/answer_key_template.md` 양식대로 각 문항별 정답/난이도/유형/배점/근거
   문장/해설(오답 분석 포함)을 작성한다. 서술형은 모범답안 + 부분점수 채점 기준.
3. 마지막에 정답 표 부록(문항/정답/배점/난이도/유형 5열) 필수.
4. 파일명: `{학년}_{학기}_{시험명}_{과목명}_정답해설.docx`
5. `/mnt/user-data/outputs/` 로 복사 후 시험지 hwpx와 함께 `present_files` 로 제시.

## 자주 하는 실수 (반드시 회피)

1. **meta 정보 확인 누락**: school/grade/semester/exam_name/subject를 안 물어보고 기본값(심인고/2학년/2학기/중간고사/영어II)으로 그냥 출력 — 사용자 학교 이름이 아닌 게 찍혀 나감. Step 1에서 반드시 확인.
2. **stem/choices에 번호 직접 삽입**: 자동 번호와 중복돼 "1. 1." 처럼 이중 표시. Step 3/4 체크리스트 참조.
3. **미지원 유형을 억지로 지원 유형인 척 조립**: "⚠️ 수동 마무리" 유형을 `plain_choice5`로 통째로 우겨넣으면 표/박스가 빠진 채로 나간다 — 반드시 사용자에게 "이 문항은 한글과오피스에서 표를 직접 넣어야 함"을 명시.
4. **build_exam.py 검증 실패 무시**: `[FATAL]` 출력이 있는데도 파일을 그대로 전달 — 열리지 않거나 스타일이 깨질 수 있다. 반드시 통과 후 전달.
5. **창의 유형 남발**: 사용자 의도는 "수능형 우선 + 창의 1-2개". 객관식 18문항 중 3개 이상 창의 유형을 넣지 말 것.
6. **지문 부족 무시**: 지문 < 문항 수일 때 임의로 지문을 합치거나 분할해 만들지 말 것. 사용자에게 부족함을 알리고 멈춘다.
7. **발문 자유 창작**: 첨부 예시 파일에 없는 발문 표현 금지. (예: ❌ "다음 글의 메시지를 가장 잘 나타낸 것은?" → ✅ "다음 글의 요지로 가장 적절한 것은?")
8. **정답·해설 docx에 난이도 라벨 누락**: [상/중/하] 누락 금지.
9. **정답 해설에 오답 근거 모호**: "왜 ②가 오답인가"를 한 줄이라도 써야 함.
10. **docx 스킬 무시(정답해설 작성 시)**: `/mnt/skills/public/docx/SKILL.md` 참고 필수.
11. **서술형 답란 줄 수 부족**: `num_answer_lines` 를 너무 작게 잡으면 학생이 답을 쓸 공간이 없음. `assets/exam_template.md` 의 R2 표 준수.
12. **hwpx XML을 손으로 편집**: 절대 금지. 반드시 `scripts/build_exam.py` 를 통해서만 생성/수정한다.

## 참조 파일 (필요 시 view)

- `references/hwpx_build_guide.md` — **hwpx 조립 방법과 JSON 스펙 전체 형식 (Step 5 진입 전 필독)**
- `references/question_types_objective.md` — 객관식 18종 출제 표준 + HWPX 조립 매핑
- `references/question_types_descriptive.md` — 서술형 11종 출제 표준 + HWPX 조립 매핑
- `references/difficulty_calibration.md` — 난이도 [상/중/하] 판정 기준 + 배점 매핑
- `references/creative_types.md` — 창의 유형 풀 (사용 가능 1-2개 한정)
- `assets/exam_template.md` — 문항 작성 시 참고할 서식 규칙(번호/배점/각주/박스/답란줄수)
- `assets/answer_key_template.md` — 정답·해설지(docx) 표준 양식
- `assets/spec_example.json` — "영어II" 템플릿에서 8가지 블록 유형을 모두 사용하는 동작 검증된 예시 스펙
- `assets/spec_example_common2.json` — "공통영어2" 템플릿 + `abc_table` 을 포함한 동작 검증된 예시 스펙
- `scripts/build_exam.py` — hwpx 조립 CLI (`python3 build_exam.py spec.json out.hwpx`)
- `scripts/blocks.py` — 블록 유형별 빌더 함수 + 템플릿별 앵커 좌표(`TEMPLATES` 딕셔너리)
- `scripts/hwpx_engine.py` — hwpx 저수준 조작 엔진(클론/텍스트치환/검증)
- `scripts/inspect_template.py` — 새 템플릿을 추가할 때 앵커 좌표를 찾는 진단 도구
